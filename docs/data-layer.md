# Data layer (F03)

## Migrations

1. `20261112172103_init` — generated by Prisma from `schema.prisma`: PostGIS extension,
   enums, 34 tables, indexes and composite tenant-aware foreign keys.
2. `20261112172200_integrity_rls` — hand-written SQL for what Prisma cannot model:

| Concern                  | Mechanism                                                                                  |
| ------------------------ | ------------------------------------------------------------------------------------------ |
| Money                    | `numeric(18,2)` + `currency_code char(3)`; CHECK amount ≥ 0 and ISO-style code             |
| One approved budget      | Partial unique index `budget_versions_one_approved_per_scheme`                             |
| Allocation ceilings      | `budget_allocations_enforce_ceiling` trigger; ceiling row locked `FOR UPDATE`              |
| Ceiling reductions       | Triggers reject lowering a version/allocation below what is allocated beneath it           |
| Verified facts immutable | `prevent_verified_mutation` on expenditure, releases, submissions; measurements locked too |
| Corrections              | New row with `supersedes_id` and non-blank `correction_reason`                             |
| Maker-checker (defence)  | CHECK `verified_by <> submitted_by` on expenditure                                         |
| Audit                    | `audit_events` rejects UPDATE/DELETE/TRUNCATE (trigger) and grants are insert/select only  |
| Jurisdiction tree        | `jurisdictions_set_ancestry` maintains `ancestry`, rejects cycles; re-parenting propagates |
| Tenant isolation         | RLS policy `tenant_isolation` on every `tenant_id` table, using `app_current_tenant()`     |

`schema.prisma` and migrations are kept in sync by `pnpm db:drift-check` (also in CI).

## Synthetic seed (`ASSAM-DEMO`)

Reference date `2026-11-11`, FY `2026-27`, all amounts INR.

- Jurisdictions: Assam (synthetic demo state) → District A/B → Co-districts A1, A2, B1, B2
- Agencies: 3 implementing (roads, water, facilities) + 1 planning cell
- 12 schemes `DEMO-001`…`DEMO-012` (4 road, 4 water, 4 public facility)
- 9 users (one per role template plus a second state planner for maker-checker), with tenant- or jurisdiction-scoped role assignments
- 2 overdue milestones, 3 pending submissions, 1 returned, 2 verified
- 3 alerts from illustrative rules; deliberate variances (e.g. `DEMO-005` verified
  expenditure exceeds verified releases; `DEMO-007` low release vs budget)
- `DEMO-001` reproduces the §5 worked example: ₹1 crore approved, ₹70 lakh verified
  releases, ₹55 lakh verified expenditure, 40% verified physical progress

These figures are asserted in `apps/api/test/integration/seed.int-spec.ts`. No metric
calculation API exists yet; the percentages are not computed by application code.
